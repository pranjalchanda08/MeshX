Detailed Description

Abstract base class for all UVP logical (functional) models.

Each concrete subclass represents one functional unit within a UVP element, identified by a unique func_id registered at construction time.

Routing is performed by can_handle(): the default implementation returns true when ctx->func_id matches the registered func_id. Subclasses MUST NOT use param_size as a routing criterion (REQ-005).

Ownership: instances are held by meshXUVPElement as std::unique_ptr<meshXLogicalModel> entries in logical_models.
