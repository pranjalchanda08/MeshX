28/**
29 * @class meshXLogicalModel
30 * @brief Abstract base class for all UVP logical (functional) models.
31 *
32 * Each concrete subclass represents one functional unit within a UVP element,
33 * identified by a unique @c func_id registered at construction time.
34 *
35 * Routing is performed by @c can_handle(): the default implementation returns
36 * true when @c ctx->func_id matches the registered @c func_id. Subclasses
37 * MUST NOT use @c param_size as a routing criterion (REQ-005).
38 *
39 * Ownership: instances are held by @c meshXUVPElement as
40 * @c std::unique_ptr<meshXLogicalModel> entries in @c logical_models.
41 */
42class meshXLogicalModel {

51 /**
